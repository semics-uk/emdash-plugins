Harden the signing ceremony and its evidence (Phase 1 review, T117). A GET of `/sign/[token]` no longer records the first view, since mail scanners prefetch emailed links: `public/session` records `signer.viewed` (and `sent → in_progress`) only with `open: true`, which the sign page sends with its first sign or decline post. `public/session` returns the consent wording's SHA-256 as `consent.sha256`; `public/submit` requires it as `consentSha256`, refuses a submit made against wording that has since changed (`CONSENT_CHANGED`), and records it on `signer.consented`, the signer and the certificate. Drawn signature points must lie in 0–1. The session lookup is refused for an IP over the ceremony failure limit (R29), with one counter for session, submit and decline. Session, submit and decline decrypt the integration master key only for an integration's envelope, so a lost `EMDASH_ENCRYPTION_KEY` never blocks a plain signature. Admin `envelope.created`, `envelope.sent` and `envelope.voided` events record the acting user's id. Resend writes a missing `envelope.sent` only at its place after `envelope.created`. Overlapping `intent-finish` runs derive the same invitation token. The signed PDF renders the snapshot's Markdown as the ceremony does. The audit timeline's page action has a handler. Without a site URL no email with a relative link is queued and the admin says why.

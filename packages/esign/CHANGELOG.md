# @semics-tech/emdash-esign

## 1.0.0-rc.1

### Minor Changes

- b037939: Attendee signing list on the booking page (T133, R95; the routes behind it are Events Pro's). When Events Pro describes a waiver booking's seats, `/booking` lists every attendee as Signed or Waiting, with a "Sign now on this device" button (the attendee signs on the buyer's phone or a front-desk tablet; a minor's guardian signs for them), "Resend invitation" for adults invited by email, and a form to correct the names and emails of attendees who have not signed until the site's cutoff. Every action is a plain form post: no JavaScript is needed. Free shows nothing new. E-sign's `public/envelopes/from-intent` honours two optional intent fields (protocol §5.1, §8.1): `resend: true` emails the open envelope's invitation again with a fresh link, and `replace: true` voids the open envelope for the seat (audited as the integration) unless it already names that signer, and never creates one. An older e-sign ignores both.

### Patch Changes

- fb2f7f0: Fixes two bugs found by the Pro playground e2e (T135). An integration client could create only one envelope on a real site: the `clients` collection declared `clientId` unique, and EmDash 1.2 builds a unique index over every collection of the plugin, so the second envelope from the same client (which also carries `clientId`) failed with a UNIQUE constraint error. The index is gone (EmDash drops it on upgrade; a client's document id is its client id, which keeps it unique), and the client is read by id. A guardian's signing page also showed "Signing as guardian for [object Object]": it now names the child.

## 1.0.0-rc.0

### Major Changes

- f0e1e43: 1.0: the trust contract is frozen (T106). Each core's capabilities, allowed hosts, public routes, MCP tools and hooks are recorded in its `trust-contract.json` and checked by a test; adding any of them is now a major version that operators consent to again. Both manifests declare the EmDash range they support (`release.requires`: `env:emdash` `>=1.2.0 <2`), so EmDash and the registry refuse an install on a host outside it.

### Minor Changes

- cb6f727: Add the hash-chained audit trail (`audit_events`): `hash_n = SHA256(hash_n-1 ‖ event)` over salted commitments of personal fields, so the retention purge never breaks verification; create-only appends that never fork; an exported chain verifier and `finalEnvelopeHash`. Envelope create, send and from-intent now write `envelope.created` / `envelope.sent` events, and every envelope carries a private `piiSalt`.
- 936db54: Add envelopes: private `envelopes/create`, `send`, `get` and `list` routes, snapshots frozen at send with `docSha256`, the envelope status machine, and `public/envelopes/from-intent` (verified `esign-intent/1` intents, idempotent per `(cid, ref)`).
- 20f9c38: Unsigned envelopes now end: an hourly `expire` task closes `sent` and `in_progress` envelopes past their `expiresAt` (audited `envelope.expired`), so retention can purge them. Deletion on request by signer email also finds drafts (new indexed `signerEmail`). Automatic reminders stay Pro.
- 9c403aa: Harden the signing ceremony and its evidence (Phase 1 review, T117). A GET of `/sign/[token]` no longer records the first view, since mail scanners prefetch emailed links: `public/session` records `signer.viewed` (and `sent → in_progress`) only with `open: true`, which the sign page sends with its first sign or decline post. `public/session` returns the consent wording's SHA-256 as `consent.sha256`; `public/submit` requires it as `consentSha256`, refuses a submit made against wording that has since changed (`CONSENT_CHANGED`), and records it on `signer.consented`, the signer and the certificate. Drawn signature points must lie in 0–1. The session lookup is refused for an IP over the ceremony failure limit (R29), with one counter for session, submit and decline. Session, submit and decline decrypt the integration master key only for an integration's envelope, so a lost `EMDASH_ENCRYPTION_KEY` never blocks a plain signature. Admin `envelope.created`, `envelope.sent` and `envelope.voided` events record the acting user's id. Resend writes a missing `envelope.sent` only at its place after `envelope.created`. Overlapping `intent-finish` runs derive the same invitation token. The signed PDF renders the snapshot's Markdown as the ceremony does. The audit timeline's page action has a handler. Without a site URL no email with a relative link is queued and the admin says why.
- cbaaea2: Add the Integrations admin page: create integration clients (pairing string shown once), revoke, and generate the master key.
- 2436cca: An envelope can carry an uploaded PDF as its document (`document`, E-sign Pro's PDF templates): `public/session` describes it (file name, size, pages; no text snapshot is read) and the signing page offers links to open or download it beside its SHA-256, never an embed. The Free core never signs such an envelope (`ENVELOPE_CLOSED`, nothing written) because it cannot show or stamp the PDF; declining still works.
- a854f7f: Retention (ES-FR-22): a daily `retention` job deletes personal data once the personal-data period has passed (default 12 months after an envelope closed) and the signed record (PDF, document, audit trail) once the signed-records period has passed (default 7 years). The audit chain still verifies after the first purge and `/verify` still matches the signed PDF until the second. Open envelopes are never touched. The Envelopes page can delete one signer's or one envelope's personal data on request. Smaller backend: packed font metrics and one shared ISO-time helper.
- c947c86: Add the `esign-request` Portable Text block and the `/_esign/start` form endpoint for self-serve signing forms. The route behind them, `public/self-serve/start`, is an E-sign Pro feature; on Free the block shows a short "not available" note instead of a form. Add `esignUi()`'s editor block and the `./astro/SelfServeBlock.astro` and `./astro/self-serve-endpoint` exports.
- 7868030: Envelopes with several signers (made by E-sign Pro) are handled safely by the Free core: each signer's first view and decline is recorded as their own audit event (`data.signer`), Free never completes such an envelope (a signature is refused with `ENVELOPE_CLOSED` and nothing is written, so a site switched back from Pro keeps a half-signed envelope intact), the signed PDF and certificate list every signer, and the signing page shows a waiting state while other signers still have to sign. New `ceremonyHandlers` seam (`src/seams.ts`) for an edition that routes several signers, a `SIGNING_OUT_OF_TURN` error code, and the schedule flag moves to v7 for the Pro `reminders` task.
- f7d4506: Add the signature pad to the signing page. With scripts on, the signer may also draw their signature (mouse, touch or pen) with keyboard-reachable Undo and Clear; typing the name stays required and works without JavaScript. The pad keeps vectors only (`{ v, w, h, strokes }`, whole-pixel points, at most 64 strokes), never an image. Its script is inlined and allowed by hash in the page's Content-Security-Policy. Fixes `/sign/[token]` calling the core under the default plugin id instead of the integration's configured one.
- c14c6f8: Add the signed PDF: a one-shot `signed-pdf-<envelopeId>` cron job, scheduled by `public/submit` at completion, renders the document, the signature and a certificate of completion (every audit event, the audit head and `finalHash`) once, stores it in `artifacts` as 256 KiB base64 chunks and records `pdfSha256`. `public/download` serves the stored bytes through a 15-minute signed link (`esign/download`); `public/session` (for the signer of a completed envelope) and `envelopes/get` return that link once the PDF is ready.
- 89a5efe: Add `<SigningCeremony>` (`@semics-tech/emdash-esign/astro/SigningCeremony.astro`), now used by `/sign/[token]`. The snapshot is parsed into a small allowlisted Markdown tree (headings, paragraphs, lists, quotes, code, emphasis, safe http(s)/mailto links) and rendered as escaped text only, with the exact hashed text and its SHA-256 beside it. The page sends a strict Content-Security-Policy (`ceremonyCsp()`) that allows only the ceremony's own inlined script and style by hash. With scripts on, Sign stays disabled until the consent box, intent box, typed name and required fields are complete, and after signing the page polls `public/session` and shows the signed PDF's download link. `handleSign` now also posts drawn signatures (pad `{ v, w, h, strokes }` normalised to 0-1 points, at most 32 KB) and session-declared field values; the no-JS form path is unchanged.
- 221308b: E-sign: signing intents now only start envelopes from templates marked "Available to integrations" (a new toggle on the template forms; existing templates start switched off, so turn it on for the templates your Events site uses). Consumed intent nonces are deleted by an hourly `nonce-sweep` task once they can no longer be replayed. Both cores re-run their one-time schedule check after this update so the new task is scheduled.
- abb8f62: Add private `templates/create`, `update`, `get`, `list` and `archive` routes with versioned Markdown templates.
- 4c6b496: Translations and right-to-left layouts for the UI kits (T102). Every text the Events and E-sign components, pages and client scripts show now comes from `src/i18n` (exported as `./i18n`), which ships English and Arabic. Components take a `locale` prop; without one they use the page's locale when the site configures Astro i18n, else British English. Each component sets its own `lang` and `dir`, the injected pages set them on `<html>`, and the styles use logical sides, so Arabic pages mirror. Client scripts read their messages from the page instead of carrying English. The sandboxed cores are unchanged: they still answer with codes, and the message tables stay out of the backend bundle. `docs/i18n.md` explains how to add a language.

### Patch Changes

- c694a8f: Accessibility fixes from the WCAG 2.2 AA audit (T101). On the sign page's email-code step, the code box has a hint. Every refusal shows inside the step and is linked to the box, and a wrong, expired or locked code marks the box invalid. Both of the step's forms return to the step (`#esign-otp`). A sign-form field to fix is described by the message that says why. The Turnstile security check switches to its compact size in a container narrower than 300 px, so the booking widget, the waitlist form, the booking-with-waiver form and the self-serve block do not scroll sideways on a 320 px screen.
- 3843621: Smaller sandbox backends with no change in behaviour. Events validates checkout bodies with a small built-in validator instead of `zod/mini` (same rules, same issue paths and codes), both cores drop unused shared code, and repeated helpers now exist once. The Events backend goes from 119.8 KiB to 95.1 KiB and E-sign from 100.9 KiB to 99.3 KiB, well under the registry's 128 KiB per-file limit.
- 68df531: Schedule recurring cron tasks even when EmDash never runs `plugin:activate`, which is the case for cores listed under `sandboxed: [...]` in `astro.config.mjs`. Events now sweeps expired holds and sends its emails on an npm/config install, and E-sign drains its outbox. The first public event read, admin page load, template creation or verify-page call schedules them once.
- 2b99566: Registry listings and docs (T103). Both manifests gain a display name, keywords, the profile sections (description, installation, FAQ, security, kept in `listing/`) and release images (icon, banner, screenshots made by the playground's Playwright spec). No capability, host, storage or route changed. The READMEs now point at the operator guides in `apps/docs`, and the E-sign retention notes say that the certificate keeps the participant's (minor's) name and the signed PDF keeps "Details entered by the signer" until the signed-records period ends.
- 7897b41: Phase 1 review fixes. The sign, signed-copy and verify pages pass `Astro.request` to `callPublicRoute`, which now carries the visitor's user agent, client-IP headers and Cloudflare `cf` object onto in-process route calls (never cookies, credentials or the Referer), so audit events record the signer's IP and user agent and per-IP limits apply per visitor. The default consent wording is now "I agree to use electronic records and an electronic signature for this document." and no longer claims the effect of a handwritten signature. The signature hash covers the values the signer entered and is salted with the envelope's audit salt, and the signed PDF lists the entered values. The sign and verify pages refuse cross-site form posts (403), since EmDash turns Astro's origin check off. The admin envelope list pages past the newest 100 (keeping the status filter), and the new-envelope form takes signer fields, one per line as `key: Label`, ending in `*` when required.
- 4919885: Signed receipts for integrations (protocol §5.2, §8.2-§8.5). When the signer signs or declines an envelope an integration created, `/sign/[token]` sends the browser back to the intent's return URL with the receipt in the URL fragment (`#receipt=`), never a query string. `public/receipts/lookup` answers a client-signed lookup with `none`, `pending` or the terminal receipt (with `pdfSha256` once the signed PDF is stored). `public/templates/catalog` lists the templates marked "available to integrations". Decline and void now record `closedAt`, the receipt's `at`.
- a81557e: The integration injects `/_events/opt-out`, the page behind the unsubscribe link in Events Pro's reminder and update emails: opening it changes nothing, its button asks the core's `public/mail/opt-out` (Events Pro). The self-scheduling flag moves to `cron:scheduled:v11` so sites already scheduled pick up Events Pro's `reminders` task.
- 4a3300b: Waitlist for sold-out events. With "Waitlist when sold out" on, the booking widget shows a "Join the waitlist" form once tickets (or a date) are sold out. When seats come free, the new `waitlist` cron task (every minute) holds them for the first person in line for 24 hours and emails a one-time claim link; claiming it on the booking page confirms a free booking (or goes to payment), and an unclaimed offer passes to the next person. Joining has a bot check and a per-connection limit. Waitlist entries are deleted by the retention job after the retention period and by the admin's "Delete personal data" (by email). The schedules flag moves to v9, so both cores schedule their recurring tasks once more.
- 0981cf3: Phase 3 review fixes. `public/envelopes/from-intent` hands a signing token for an existing envelope only to an inline intent that names the signer the envelope awaits (same email and capacity): Events' door-signing link now works for an attendee whose emailed waiver is still open, and an intent for anyone else can no longer take over a signer's session. The waiver page's "Try again" works in a browser (the booking cookie never reached `/_events/waiver`; the flow now keeps the access token in an HttpOnly, SameSite=Strict cookie on that path). Both manifests now declare the secret settings their Pro builds store (Events: `licenceKey`, `stripeSecretKey`, `stripeWebhookSecret`; E-sign: `licenceKey`), labelled "(Pro)" and ignored by Free: without them a site switched from Pro back to Free could not read its settings, so checkout and the admin failed (trust-contract change: three and one new secret settings, BUILD-PLAN R44). The booking page stops asking e-sign about a seat whose declined, voided or expired receipt is already recorded, until continue sends that seat a new intent.
- 8369d39: The UI helpers under `src/astro/lib` are exported as `./astro/lib/*` (for example `callPublicRoute`, `forwardReceipt`, `handleSign`, `ceremonyCsp`), so the suite (T065) can compose them without importing `.astro` files.
